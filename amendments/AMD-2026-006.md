# Amendment: Google Workspace Governed Integration Plane

## 1. Rationale

Google Workspace MCP servers expose a broad tool surface (mail, drive, docs, automation). Exposing that surface directly to conversational or voice layers creates **unbounded execution risk**. This amendment ratifies **AIOS-SPEC-007** as the binding contract: **Intent Layer → Workspace Intent Router → Integration Control Plane → MCP Adapter → Google APIs**, with **Layer 1** governance scope classes and **Layer 2** operational intents, **one intent → exactly one scope class**, policy packs POL-WORKSPACE-001–006, phased rollout, and audit requirements.

---

## 2. Proposed Changes

### Change 1: Ratify AIOS-SPEC-007

**Affected Document:** AIOS-SPEC-007 (draft → ratified upon Council process)  
**Effect:** Google Workspace integration MUST comply with SPEC-007; MCP is execution substrate only.

### Change 2: Extend AIOS-SPEC-003

**Affected Document:** AIOS Agent Integration Protocol  
**Effect:** Assistants MUST emit governed `workspace.*` intents per SPEC-007; no direct MCP tool invocation from agent layer.

### Change 3: Extend AIOS-SPEC-006

**Affected Document:** UI Component Registry Standard  
**Effect:** Register Workspace canvas surfaces (`workspace_hub`, service hubs, editors) with footer, load states, and exit contracts.
