# AMD-2026-012-ADD-001 — Loop Exit and Discovery-First Voice Sequencing

## 0. Status and intent

| Field | Value |
|-------|--------|
| **Status** | **`draft` `0.2.0`** — addendum to **[AMD-2026-012](AMD-2026-012.md)** |
| **Purpose** | Extend shell authority and voice-first law with explicit loop-exit obligations and discovery-first sequencing rules so voice-first systems do not collapse into dashboard-first or menu-first planning. |

## 1. Purpose

This addendum establishes two binding rules:

1. voice-first systems SHALL offer an explicit path to exit the progress loop
2. voice-first planning SHALL begin with discovery, intent, schemas, routes, and storage before dashboard or menu composition

## 2. Governing principle

Voice-first systems SHALL be judged by outcome direction and exit clarity, not by how much interface chrome or conversational continuity they can produce.

## 3. Loop-exit rule

The shell SHALL provide a user-comprehensible path from:

- declared intent
- to next real step
- to evidence
- to closure, reset, or explicit stop

For this addendum, evidence means an inspectable artifact, state pointer, route, packet, export, or review surface that shows what the system did, what state remains active, and how the user can continue, stop, or hand off.

A user-comprehensible path SHALL use visible controls, explicit state labels, or explicit command equivalents that a reasonable user can follow without guessing hidden system state.

Conversation quality, reassurance, or polished summaries SHALL NOT count as closure by themselves.

## 4. Minimum loop-exit options

At minimum, the shell SHALL provide explicit exit options that provide the functional equivalent of:

- stop and clear state
- export current packet or evidence
- hand off to human review
- reset the active intent
- freeze the current work state for outside inspection

## 5. Discovery-first sequencing

For AI-first and especially voice-first systems, planning SHALL NOT begin with dashboards, dropdown menus, or omnibus UI composition as the primary architecture move.

The required sequence SHALL be:

1. discovery
2. architecture cartography
3. capability extraction
4. schema review
5. route review
6. storage / state review
7. governance breach audit
8. intent and loop-closure design
9. only then shell and UI composition

## 6. Multi-agent discovery

When current-system structure matters, discovery SHALL use one or more specialized passes aligned with:

- `AIOS-DISCOVER-AGENT-PROCESS-001`
- `AIOS-PRE-ARCHITECTURE-DISCOVERY-AGENT-001`

These passes MAY include:

- cartography
- capabilities
- schemas
- routes
- storage
- rendered-surface inspection
- artifact integrity checks

## 7. Anti-dashboard-first rule

The shell SHALL NOT use dashboard-first or tool-catalog-first planning as a substitute for intent architecture.

Menus and dropdowns MAY remain subordinate fallback affordances, but they SHALL NOT replace:

- intent discovery
- loop-exit clarity
- shell authority
- or rendered proof of the active path

## Final principle

If a voice-first system cannot help the user exit the loop and cannot discover the system before composing the chrome, it is not ready to claim voice-first authority.
