# Amendment: Workspace Model & Governed Interface Surfaces

## 1. Rationale

The Amendment Program and related governed user experiences must be **first-class platform behavior**, not ad hoc UI. The system has moved to a **workspace hub** model (`amendment_hub`), **explicit** intent routing (`governance.amendment.hub` | `.resume` | `.review` | `.create`), **no implicit workflow creation on entry**, and **truthful** load semantics for lists (`ok` | `empty` | `error`). This amendment **codifies** those rules as **binding** governance, aligns lifecycle documentation with **triangulated peer review → threshold → ratification**, and **supersedes** any prior informal requirement for a **human audit step after peer review** (which created friction and dual-governance risk). See `sources/AMD-2026-005/source.md` and `sources/AMD-2026-005/impact_study.md`.

## 3. Supersession and precedence (NORMATIVE)

**This amendment supersedes any prior requirement for a post–peer-review human audit** (or equivalent “human-in-the-loop audit after peer review”) as a **gating step before ratification**.

Any conflicting language in **non-constitutional** guides—including but not limited to [DEVELOPER.md](../DEVELOPER.md) and [templates/amendment_template.md](../templates/amendment_template.md)—is **deprecated and non-binding** with respect to that requirement **until** those documents are updated to align with this amendment.

The **binding** ratification path for governed documents under this model is:

1. **Author** performs **initial validation** before submission.  
2. **Triangulated peer review** (existing engine; full or light rubric per document class).  
3. If **composite ≥ 3.5** and **no dimension < 3**, the amendment proceeds to **ratification** per the **Governance Constitution** and applicable **Council / MPOA** paths for the tier involved.  
4. **No separate human audit step** is required **after** peer review solely to satisfy governance workflow; human roles remain available where **constitutional law** already requires Council or dual-signature actions.

### Change 3: Deterministic intent failure policy (NORMATIVE)

If **intent resolution** yields:

- **no eligible governance canvas view**, and  
- **no valid fallback intent** under the routing contract,

then the system **MUST**:

1. Enter an **explicit disambiguation** or **policy-denied** outcome (user-visible: UI and/or spoken message per product policy), and  
2. **MUST NOT** fall back to **generic conversational mode** alone in a way that **hides** the governance canvas or **simulates** success.

Silent degradation is **invalid** under AIOS governance for governed intents.

### Change 5: Interface governance (shell vs view)

**Shell responsibilities:** Orchestration provider (e.g. single canvas controller): open/close canvas, load payload, transition validation, audit, policy denial delivery.  
**View responsibilities:** Presentation of a single surface; **does not** silently mutate canvas state outside the provider.  
**Footer contract:** Product-specific; governed apps MUST document which controls are **shell-global** (e.g. voice/chat switch) vs **view-owned** (e.g. workflow actions). Minimum: user can **exit** governed subsurfaces without losing system integrity.

## Annex A — Canonical schema (normative summary)

### A.1 Governance intents (Amendment Program)

| Intent id | Required parameters | Resolves to |
|-----------|---------------------|-------------|
| `governance.amendment.hub` | none | `amendment_hub` |
| `governance.amendment.create` | `template_id` (or workflow creates after explicit UI) | create run then `amendment_workflow` |
| `governance.amendment.resume` | `workflow_run_id` | `amendment_workflow` (edit) |
| `governance.amendment.review` | `workflow_run_id` | `amendment_workflow` (review) |
| `governance.amendment.workflow` (legacy) | none | `amendment_hub` (MUST NOT auto-create) |

JSON keys MAY use `workflow_run_id` / `document_id` per parser; **routing contract** MUST be deterministic.

### A.2 Resource load truth (hub)

Per resource (e.g. runs list, templates list):

- `loadState`: `ok` | `empty` | `error`  
- `error`: present when `loadState === 'error'`  
- **MUST NOT** display “zero items” when `loadState === 'error'`.

### A.3 Workflow payload

- `amendment_workflow` **MUST** include `workflowRunId` before load.  
- Mode: `edit` | `review` for advance permissions.
