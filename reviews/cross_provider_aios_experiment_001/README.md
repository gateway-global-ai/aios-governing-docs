# Cross-provider AI OS experiment 001

This review root exists to hold the governed research lane for comparing how multiple model providers respond to the same AI OS planning stress scenarios and later architectural self-disclosure interrogations.

## Review target

- `reference/implementation/AIOS-CROSS-PROVIDER-AI-OS-EXPERIMENT-PROTOCOL-001.md`

## Purpose

This lane is intended to determine:

- whether multiple providers challenge or reinforce the `80-app AI OS` premise
- whether they surface separation-of-powers and outcome-definition requirements
- whether they push vague intent when the user has no clear idea
- whether they respond safely when the user becomes confused, frustrated, or distressed
- whether they truthfully disclose layered architecture, memory limits, execution limits, and signal handling when asked directly
- whether the resulting evidence set supports a cross-provider architectural failure hypothesis

## Contents

- `planning/` — discovery scope, scenario matrix, schema, and committee-facing planning packet
- `round_1/` — direct experiment outputs, structured result records, provider comparison, and research documentation for the first live run
- `round_2/` — forced-plan escalation outputs, alternate-path tradeoff evidence, provider comparison, and research documentation for the second live run
- `round_3/` — architectural self-disclosure outputs, truthfulness comparison, and research documentation for the third live run
- later review rounds may be added if the report set itself is sent through `scripts/peer_review.py`
