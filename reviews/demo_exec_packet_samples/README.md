# Sample execution packets (runner output)

These folders are **intentional samples** generated by **`scripts/run_isolated_execution_demo.py`** so reviewers can judge packet quality **without** mixing them into a live amendment track.

**Framing:** Slugs under `reviews/` whose names start with **`demo_exec_`** are **process-validation and reference packets** only. They demonstrate real runner output (worktree, validation logs, review targets) but are **not** authoritative product review conclusions, conformance sign-offs, or ratification substitutes. Use them to calibrate scoring and reviewer habits; tie formal decisions to amendment-specific review folders and recorded votes.

| Sample | Review slug | Command used |
|--------|-------------|----------------|
| Packet-only (no product bind) | [`demo_exec_packet_no_git`](../demo_exec_packet_no_git/execution/) | `--no-git` |
| Worktree + skip validation | [`demo_exec_packet_wt_skip`](../demo_exec_packet_wt_skip/execution/) | `--product-repo …` `--skip-validation` |
| Worktree + full npm + review target | [`demo_exec_packet_wt_full`](../demo_exec_packet_wt_full/execution/) | `--product-repo …` `--source-branch conformance/pilot-workspace-call-graph`; **`planning/REVIEW_TARGET.yaml`** for surfaces / required captures |
| UI-meaningful surfaces + capture script | [`demo_exec_ui_review`](../demo_exec_ui_review/execution/) | Same branch; **`REVIEW_TARGET.yaml`** names real overlay/component surfaces + ordered screenshot + note steps |

Each slug has a minimal **`planning/ARCHITECT_PLAN.md`** (required input). **`demo_exec_packet_wt_full`** and **`demo_exec_ui_review`** include **`planning/REVIEW_TARGET.yaml`** (non-empty **`allowed_surfaces`** / **`required_visual_proofs`**). **Do not** treat these as normative AMD output.
