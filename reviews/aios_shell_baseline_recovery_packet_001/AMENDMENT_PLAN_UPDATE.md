# Amendment plan update

## Purpose

This document records the valid concern set that should shape any future shell-baseline addendum or amendment planning work after the supporting packet is revised and re-reviewed.

It does **not** open a new amendment by itself.

## Final adopted concern set

The seven-review advisory panel supports carrying the following concerns forward into amendment planning:

1. **Taxonomy is a first-order issue**

The future amendment/addendum plan must treat packet taxonomy, review semantics, and governed artifact classes as core structure, not editorial polish.

Target concerns:

- alignment to `AIOS-REVIEW-PACKET-TAXONOMY-001`
- correct role of supporting packet vs review packet vs binding doctrine
- stable handoff semantics for synthesis, gate, and status artifacts

2. **Authority must be explicit**

Any future amendment plan must separate:

- what a supporting packet can do
- what a review packet can record
- what only a ratified amendment, council motion, or other binding vehicle may authorize

Target concerns:

- no implied gate authority without named governing source
- no implied freeze/approval effect without binding vehicle
- no silent transition from evidence packet to law

3. **The 14-capability baseline must have an explicit authority trail**

The future plan must state whether the baseline is:

- directly derived from existing doctrine
- a declared review basis awaiting approval
- or a mixed baseline requiring explicit harmonization

Target concerns:

- source of truth for each capability
- relationship between the packet gap map and future doctrine text
- auditable mapping from capability to governing anchor and implementation evidence

4. **Foundation surface gaps must be addressed directly**

The next plan must explicitly address the missing or incomplete foundation surfaces repeatedly cited across the review set:

- identity-bound administrative authority
- account creation and OTP verification
- account/profile display and edit
- document and storage workflows
- dual-lane voice switching
- governed agent-control surfaces

5. **Evidence portability and freeze discipline must improve**

The next plan must require:

- repo-relative evidence paths
- explicit freeze metadata for reviewed implementation state
- repeatable export and review mechanics

## Recommended planning sequence

1. Revise the supporting packet.
2. Rerun review on the revised packet.
3. Confirm the final adopted concern set after rereview.
4. Open a narrow shell-baseline amendment or addendum only if those concerns still prove doctrine gaps that cannot be resolved by packet refinement, implementation correction, or specification alignment.

## Non-scope for the future amendment plan

Do not let the future amendment plan absorb unrelated work:

- broader tenant redesign
- marketplace expansion
- rich document-system scope beyond baseline foundation
- unrelated shell aesthetics

## Priority order

Priority order for future amendment planning:

1. taxonomy
2. authority and gate semantics
3. baseline capability authority trail
4. identity/profile/document foundation gaps
5. dual-lane voice and governed control gaps
6. portability and freeze discipline
