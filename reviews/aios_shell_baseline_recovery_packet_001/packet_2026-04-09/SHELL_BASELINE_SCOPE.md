# Shell baseline scope

## In scope for the thin slice

- voice-first shell entry
- greeting and first-use orientation
- new-vs-returning session classification
- command rail controls
- chat fallback
- menu and shell settings overlays
- shell state separation (`primary`, `developer`, `operator`)
- shell intent routing and deterministic shell commands
- workspace entry as a subordinate shell-controlled surface
- baseline screen artifacts, text surfaces, and disclosure behavior
- current routes, schemas, and persistence surfaces
- the gap map against the 14 required baseline capabilities

## Frozen out of this thin slice

- broader tenant workflows
- rich document system implementation beyond the baseline gap map
- new doctrine unrelated to shell-baseline foundations
- implementation work for missing capabilities
- marketplace, billing, or commercial rollouts
- generalized UI redesign outside the shell baseline

## Approval rule

No broader shell, tenant, or rich artifact work should move forward until this thin slice is reviewed and approved as the baseline foundation.

## Doctrine posture

Use ratified doctrine as authority where it exists.

Use draft addenda and draft implementation standards only as working guidance to identify missing doctrine, not as silent authority.
